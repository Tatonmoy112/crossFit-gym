## Purpose, content and boundary

Implement one desktop navigation component for future header assembly. Preserve the four groups and all 15 labels/destinations in `src/content/navigation.ts`: About, Training, Explore and Visit us. Group labels are disclosure buttons, not invented page destinations. No Home link is added because BrandLink owns that destination. Completing this component does not complete those items.

## Architecture and contract

- `DesktopNavigation` in `src/components/layout/desktop-navigation.tsx` is a Server Component with optional className only. It reads validated navigation content and passes plain groups to the client interaction boundary `desktop-navigation-menu.tsx`.
- Validate nonempty groups/labels, canonical root-relative destinations, unique group names and globally unique destinations with Zod. Validate destinations against the fixed route registry and actual approved location slugs. Preserve the supplied record order and values; reject preview/unknown targets. Keep validation on the server; the client uses type-only content imports.
- The client boundary uses the existing App Router usePathname hook; there is no new application provider, global store, URL write or custom router. One local open-group state controls the disclosures; outside pointer/focus listeners exist only while a group is open and clean up on dismissal/unmount. Strip trailing slashes/query/hash for comparisons. Choose one most-specific matching link: exact match uses aria-current=page; a boundary-delimited descendant uses aria-current=location on its closest listed ancestor. `/programs-archive` must not select `/programs`; a listed detail such as `/locations/uttara` wins over `/locations`. Null/Home/unrelated paths have no current link.
- Mark the containing group with a non-color current-section cue (semibold underline) and an accessible `current section` description. Root is named `Primary navigation`, with native buttons/links/lists rather than ARIA menu/menubar roles. Triggers have native type=button, expanded/controls relationships, a decorative chevron and at least 44px targets. Only one panel is open. Closed panels do not enter the accessibility tree or Tab order.
- Pointer click and native Enter/Space toggle the disclosures; hover supplies visual feedback only. Arrow Down from an open trigger reaches its first link; native Tab/Shift+Tab remain usable. Escape closes and restores trigger focus; outside interaction closes without trapping focus. Link selection closes the panel and retains normal Next Link navigation. A pathname change resets the open panel through the keyed disclosure component's identity, without an effect that sets state.
- Show at Tailwind lg (64rem/1024px at default root size); hide and remove its contents from keyboard/accessibility navigation below lg. Hidden desktop navigation is not a mobile replacement. Future mobile navigation must cover that range before header mounting.
- Triggers use Inter 500 1rem/1.4, 8px radius, 150ms control transitions and opaque semantic states; current section is Inter 600. The panel uses the inherited surface's popover roles, input border, 16px radius, 8px padding and a 288px maximum nominal width constrained by the navigation root. Its link list has 8px padding, preserving 6px outline clearance. Panel appearance is immediate with no entrance/exit animation. Chevron changes are static; reduced motion removes control transitions.
- Keep focus at 3px/3px, text contrast >=4.5:1 and normal/wrapped labels fully visible. Wrap trigger rows under text enlargement rather than clipping or horizontal scrolling. Panels align to the list's start and stay within available width; header alignment/sticky collision behavior remains for assembly. Font failure and forced colors retain readable, operable controls.
