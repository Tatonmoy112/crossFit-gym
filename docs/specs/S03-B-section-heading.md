# S03-B: Section heading

Status: **verified for the documented scope**. Date: 2026-11-16. Item 8 in the [13-item pre-Home checklist](../pre-home-checklist.md).

## Purpose and design

Build a consistent heading group for subsections: an H2 followed by an optional description. Use the verified fluid Barlow Condensed 600 display hierarchy, semantic foreground, Inter 400 description at 16px/1.6, an 8px gap and a 65ch body measure. Start alignment is the default; centered alignment supports the existing content-state composition. The wrapper is transparent, full available width and adds no outer spacing, decorative icon, rule, background or animation. The containing section owns layout and surfaces.

No dedicated approved section-heading reference is available; this design follows the selected brand foundations and is subject to visual review. Do not invent an eyebrow, business statement, action or artwork to fill missing inputs. Test specimens remain outside business catalogs and public routes.

## Contract and boundary

- `SectionHeading({ title, description?, headingId?, align? })` is a Server Component. `title` is required plain text; `description` is optional plain text; `headingId` optionally assigns an ID to the H2; `align` is `"start" | "center"`, defaulting to start. These props all describe the same heading pattern. No polymorphic tag, H1, heading-level variant, action, arbitrary children, client state, provider or dependency is needed.
- Render one native H2. Preserve normal React escaping. Do not inject HTML, generate IDs, add a role/live region/landmark, autofocus or create a Tab stop. Consumers own meaningful nonempty content and unique IDs; approved UI/business records remain validated in `src/content`. A parent may use the supplied ID in its own `aria-labelledby`.
- Render a paragraph only for a nonblank description. Omitted, empty or whitespace-only descriptions leave no empty paragraph or placeholder. Preserve supplied display text rather than generating fallback copy.
- H2 uses the existing foundation formula `clamp(1.75rem, 1.25rem + 2vw, 3rem)` with 1.15 line height and normal letter spacing. Body uses semantic muted foreground. Both wrap long/unbroken text without truncation, clipping or fixed height. Start alignment follows RTL; center alignment centers the readable measure. Use existing tokens/CSS; do not change the foundation or stock shadcn modules.
- First integrate by replacing only ContentState's heading/description group with `SectionHeading` in center mode. Keep installed shadcn Empty as the state shell. Preserve its 12px card geometry/padding, copy, H2 semantics, no-live/no-control behavior and conditional Programs consumer. The Programs H1, Container, metadata, recovery link, global shell and indexing protections remain unchanged.
- Verify title-only and described forms on light/yellow/charcoal surfaces at 320/375/768/1280/1920px, with doubled/spaced text and RTL. Keep content readable with blocked fonts, reduced motion, forced colors and JavaScript disabled. Actual zoom, manual screen-reader review and final design approval remain distinct from automated reflow evidence.
- This iteration excludes page introductions/H1, breadcrumbs, new page sections, content authoring, discovery controls, service features and other consumer migrations. The remaining five pre-Home items and complete 24-template scope remain intact.
