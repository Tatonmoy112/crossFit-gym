## Contract

- `Header()` is a Server Component with no public props. It composes the existing server data wrappers and BrandLink, retaining small client navigation boundaries. It adds no heading, business copy or duplicate source of destinations.
- Every exported page and the custom 404 contain one banner, followed by the existing focusable `main#main`. Skip to content stays the first Tab stop and is visibly above the header when focused. No footer or new page section is introduced.
- The header has a full-width `data-surface="charcoal"` background, semantic foreground/boundary roles and a constrained `layout-container`. Normal-flow positioning avoids obscuring content. Its inner flex layout wraps when space is insufficient; BrandLink remains readable beside or above controls without truncation. Use 16px vertical padding and a 16px gap; content width/gutters come from F01-D.
- BrandLink precedes navigation in DOM/keyboard order. At widths below 1024 CSS px, only Menu is exposed; desktop navigation is hidden from accessibility and Tab order. At/above 1024, only desktop navigation is exposed. A closed mobile menu exposes no second primary landmark. Open mobile content remains portaled with its explicit light surface and modal behavior.
- Desktop groups retain existing keyboard/disclosure/current matching. Mobile retains focus trapping, dismissal/restoration and independent body scrolling. Closing on a breakpoint crossing releases all modal isolation/scroll lock. An open desktop disclosure closes when crossing to mobile and does not reopen automatically on return. Focus from a navigation variant becoming hidden moves to the existing main fallback; focus elsewhere is left alone.
- Ordinary menu-link navigation uses the real App Router without replacing the document, closes the active menu and updates current cues. Browser Back/Forward also reset open state and current cues. Visiting a descendant marks the most specific ancestor location. Home and unrelated 404 paths do not invent a current link. BrandLink returns Home. Same-page selection dismisses normally. Preserve native modified links.
- Verify responsive fit at 320/375/768/1023/1024/1280/1920px and enlarged/spaced text, keyboard focus clearance, blocked font/logo fallback, reduced motion, forced colors and sampled WCAG AA. Browser text enlargement is distinct from manual browser-zoom approval.
- Server-rendered brand/Home and existing page recovery content remain available without JavaScript. Interactive navigation requires JavaScript; this iteration does not claim a full no-JavaScript menu implementation.

## Evidence and limits

A further desktop component regression failed because crossing to mobile retained the open panel. The final layout wraps instead of forcing the brand into remaining space; a shared focus-ownership hook preserves ownership only through visibility-driven blur, clears it on ordinary exit and supplies the existing main fallback. No assertion, accessibility rule or contrast threshold was removed to fix these issues.
