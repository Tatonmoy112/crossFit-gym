# U01-B: Navigation link

Date: 2026-11-15. Status: **verified for the documented automated scope; manual review remains open**. Parent: [rebuild plan U01](../component-rebuild-plan.md), following [U01-A Button](U01-A-button.md) and [F01 foundations](F01-design-foundations.md).

## Scope and consumers

Build one `NavigationLink` in `src/components/ui/navigation-link.tsx` for standalone navigation controls. Integrate only About's existing Back to home link; preserve its label/destination and every route/content/metadata contract. Future header/footer navigation may consume it after their own specifications. Inline prose anchors retain their natural paragraph flow and are not converted into 44px controls. Brand links, menu assembly, breadcrumbs, button-shaped CTAs, slotted Button anchor variants, providers and business actions remain separate.

The agreed foundations supply the appearance; original raster references remain absent. Use the existing Next Link primitive for root-relative paths with prefetch disabled, native anchors for HTTP(S), mailto, tel and named fragments, and no custom keyboard activation or client router provider. Do not use button roles or trigger business actions from a link.

## Interface and states

Export `NavigationLink` and `NavigationLinkProps`. Require a string href; retain native anchor props including React 19 ref, event handlers, target, rel, className and ARIA attributes. Current page is explicitly supplied as native `aria-current="page"`; route matching belongs to the eventual navigation composition. No usePathname hook, automatic prefix matching, local state or new provider is needed.

Supported destinations are root-relative paths (including query/hash), nonempty named fragments, absolute HTTP(S) URLs with hosts, and nonempty mailto/tel targets. Preserve destination semantics instead of inventing or rewriting them; Next owns internal trailing-slash normalization. Reject missing/empty targets, unnamed hash placeholders, ambiguous relative paths, protocol-relative paths, backslashes, whitespace/control characters and unsupported/malformed schemes with a clear generic TypeError. This is a component destination contract, not a business URL/phone/email validator.

There is no disabled/unavailable-link prop. A consumer with no approved destination omits the link or presents explicit noninteractive missing-content text in its own task; it must not publish href="#", a fake destination or an aria-disabled anchor that still navigates. This primitive expects a real destination and does not implement disabled-link event interception.

| State           | Contract                                                                                                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Normal          | Underlined local link color, Inter 500 1rem/1.4, 8px control radius, at least 44px inline/block target, 12px horizontal and 8px vertical padding. Natural label wrapping, no fixed height or truncation. |
| Hover           | Accent surface/foreground, underline retained; only where hover is supported.                                                                                                                            |
| Pressed         | Selected surface/foreground, underline retained, no spatial movement.                                                                                                                                    |
| Current page    | aria-current=page, Inter 600 and a 2px underline instead of 1px; non-color cue and still navigable.                                                                                                      |
| Focus           | Existing protected 3px outline/3px offset on light/yellow/charcoal, including forced colors. Caller supplies surrounding clearance.                                                                      |
| Motion/fallback | F01 control color transitions (150ms ease-out); reduced motion removes them. Local Inter and system fallback remain readable.                                                                            |

HTTP(S) destinations stay in the same tab unless the caller explicitly chooses a target. For target=_blank (case-insensitive), merge rel tokens with noopener/noreferrer and remove conflicting opener tokens, preserving other caller tokens. Append visible functional copy “(opens in a new tab)” in the hint role. When aria-label is supplied, append the same cue to that accessible name. Other caller naming overrides such as aria-labelledby require consumer review. Never add a new-tab target just because a URL is external.

Require at least 4.5:1 text contrast in all actual surface/states. Underlines persist on hover and current state has weight/thickness cues. Consumers provide meaningful visible text or an accessible name for an icon; no inferred business labels or automatic tooltips.

## Evidence and limitations

Before implementation, the runnable unstyled Next Link baseline had ten failing component cases and seven passing compatibility cases. Four desktop browser cases failed for missing 44px targets (33.59px list link and 20px About recovery link), new-tab cues and reduced-motion role; existing responsive/keyboard/axe checks passed. Two subsequent malformed HTTP destination cases failed before tightening validation: URL parsing alone accepted scheme forms without the required // delimiter. All 19 NavigationLink cases then passed, with all 36 unit/component tests passing across six files.

An initial browser import failure was test infrastructure, not an acceptance result: the installed TypeScript compiler produces per-worker ignored CommonJS output of the actual component so Next's extensionless entry loads without mocks or application import changes. Browser fixtures use that markup; Testing Library checks React callbacks/ref forwarding, and About provides actual framework hydration/navigation coverage. The isolated render may omit Next's build-time trailing slash, so browser expectations accept either slash form while preserving the actual destination/query/hash. No production routing change was needed.
