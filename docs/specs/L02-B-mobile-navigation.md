## Contract

- `MobileNavigation({ className? })` is a server-compatible wrapper supplying validated `src/content/navigation` to a small client menu. Only presentation class customization is public. No provider or shared global state.
- Below Tailwind `lg` (1024 CSS px), a native Button shows a decorative menu icon and visible “Menu” label. At/above `lg` it leaves the accessibility and Tab order. Server markup uses CSS visibility; the modal cannot remain open on desktop after hydration.
- Closed: no navigation links or modal are exposed. Open: a modal dialog named “Site navigation”, with a visible X control named “Close menu”, then one primary-navigation landmark containing four heading/list groups. All destinations are available without nested disclosures. Controls/links are at least 44px high. Browser testing at 320px with doubled/spaced text established that the close control needs compact icon presentation to preserve space for the scrolling body.
- Reuse installed shadcn Dialog root/trigger/portal/close and Radix modal primitives for focus trapping, background isolation, Escape, outside dismissal and scroll locking. Use the adapted Button and NavigationLink. Do not certify unrelated stock dialog/sheet variants.
- Initial focus goes to Close menu. Tab/Shift+Tab remain in the panel. Escape, Close menu and backdrop dismissal restore Menu focus. Ordinary link activation closes before navigation; modified clicks preserve native link behavior. A pathname change resets the open state. Crossing to desktop closes and releases the modal; if the hidden Menu would receive focus, focus the existing `main#main` fallback. Header assembly must verify this in the composed layout.
- Share canonical-path/current-link matching with desktop navigation: normalize query/hash/trailing slash; exact destination has `aria-current="page"`; the most specific slash-delimited ancestor has `aria-current="location"`; unrelated paths and unavailable pathname have no current link. Current cues use weight and underline as well as color.
- The trigger inherits light/yellow/charcoal surface tokens. Portaled panel explicitly declares `data-surface="light"`, including inside a charcoal parent. Panel uses 16px overlay radius, semantic background/text/border roles, 16px inset and maximum width 24rem. A fixed header keeps Close accessible; the body scrolls within the available dynamic viewport height, with focus clearance around links.
- Verify 320, 375, 768, 1023, 1024, 1280 and 1920px widths, short viewport, enlarged text and text spacing. Preserve visible focus and forced-colors operation. Opening/closing is immediate; control feedback uses the existing 150ms role and respects reduced motion. No new animation is required.
