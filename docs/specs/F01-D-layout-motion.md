| Interface                                            | Contract and consumer                                                                                                                                                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tailwind spacing                                     | Explicit `--spacing: 0.25rem`; standard utilities 1/2/3/4/6/8/12/16/24 produce 4/8/12/16/24/32/48/64/96px at the default root.                                                                               |
| `--content-max`, `--content-gutter`                  | 1550px inner maximum; gutter 1rem below md, 1.5rem from md (48rem), 2rem from lg (64rem). Existing Tailwind breakpoints are unchanged.                                                                       |
| `layout-container`                                   | Inline size `min(1550px, 100% - 2 * gutter)`, centered, minimum inline size zero. No internal gutter padding. Place inside full-width section backgrounds; do not nest containers and double the gutters.    |
| `rounded-control`, `rounded-card`, `rounded-overlay` | Explicit Tailwind radius roles 0.5rem/0.75rem/1rem, independent of stock shadcn multipliers. Existing generic radius roles remain for later component adaptation.                                            |
| `touch-target`                                       | Opt-in minimum inline/block size 2.75rem (44px), maximum inline size 100%; allow content to increase height. Actual primary controls must adopt it in their tasks. Inline prose links remain in normal flow. |
| `motion-control`                                     | Color/background/border/opacity transitions, 150ms, ease-out, no delay. No transition-all or spatial movement.                                                                                               |
| `motion-overlay`                                     | Opacity/transform/translate/scale transitions, 200ms, ease-out, no delay. Does not create an overlay, set placement, manage presence or implement dialog behavior.                                           |
| Motion tokens                                        | `--motion-duration-control: 150ms`, `--motion-duration-overlay: 200ms`, `--motion-easing: ease-out`. No autoplay, smooth scrolling or decorative animation is introduced.                                    |

`src/styles/layout.css` owns layout/geometry roles; `src/styles/motion.css` owns motion roles and reduced-motion protection. The globals stylesheet imports both. On each existing route shell (including 404), apply `layout-container py-8` to its existing section. Main remains the full-width landmark with id `main` and tabIndex -1; it is not the content container. No page text, section order, static parameter or metadata changes accompany this migration.

The skip link remains first in keyboard order and gains the touch-target role. Controls keep the F01-B solid 3px outline and 3px offset. Give specimens at least 6px clear space around their controls. The full-width noninteractive main landmark uses a 3px inset focus outline (offset -3px) so its outline remains inside the viewport; this is a landmark-specific exception, not a control focus change. Actual sticky regions, focus traps, portals and adjacent-control geometry still need their own component acceptance tests.

Under reduced motion, disable transitions on the two opt-in motion roles. Preserve the existing global 0.01ms animation/transition safeguard with one animation iteration; additionally reset animation/transition delays to zero and force automatic scroll behavior, including ::before/::after pseudo-elements. Preserve static transforms used for positioning: suppress their animation rather than removing placement. State and focus changes complete without depending on animation-end/transition-end events. Essential progress needs text/status in its actual component.

## Evidence and limitations
