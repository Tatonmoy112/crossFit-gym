# S03-A: Container

Status: **verified for the documented scope**. Date: 2026-11-16. Item 7 in the [13-item pre-Home checklist](../pre-home-checklist.md).

## Purpose and boundary

Expose the verified F01-D content-width/gutter rules through one composable component. A section owns its full-width background, semantics and vertical spacing; its Container constrains only inner content. Programs is the first consumer. Other routes, Header, Footer and PreviewNotice keep their existing CSS consumers until their relevant integration tasks. No design reference specific to this wrapper is available; geometry follows the approved foundations.

This iteration does not build section headings, page introductions, breadcrumbs or other page sections. Do not add a provider, dependency, public fixture route, business copy, size variant, polymorphic rendering or new layout tokens. The stock shadcn set has no container primitive to adapt; use the same local composition conventions and existing class utility.

## Contract

- `Container(props: React.ComponentProps<"div">)` renders one native div with its children in their original order. It is a Server Component by default, with no hook, client directive, state, service or generated content.
- Compose the existing `layout-container` class with caller `className` using the installed class utility. Forward native attributes and the React 19 native ref. Consumers may add vertical spacing, grid/flex layout and normal div attributes; they own any explicitly supplied ARIA/focus semantics. The component adds no role, heading, landmark, Tab stop or live region itself.
- Keep geometry in `src/styles/layout.css`: maximum 1550px (fixed CSS pixels, including with enlarged root text); equal auto inline margins; 16px gutters below 768px, 24px from 768px and 32px from 1024px at the default root font. No implicit padding, background, border, radius, fixed height or overflow clipping. Do not duplicate these values in component code or add width overrides.
- Width is relative to the available parent width, so one Container belongs inside each unconstrained section. Deliberately nesting Containers adds another set of gutters; do not nest them accidentally. Caller-supplied width/margin/padding utilities can override the contract and should not be used to simulate size variants. Children remain responsible for their own intrinsically wide media/table behavior; the wrapper does not hide overflow.
- On `/programs/`, move the existing horizontal constraint from the outer section into one Container. Keep `py-8` on the full-width section. Preserve heading, conditional content state, recovery link, metadata, root preview notice, landmarks and routes. Do not change any copy or populated-catalog behavior.
- Verify 320/375/767/768/1023/1024/1280/1920px, normal and doubled/spaced text, light/yellow/charcoal section backgrounds, and a constrained grid parent. Check RTL alignment. Font failure, reduced motion, forced colors and no JavaScript must preserve content/recovery. Root-font enlargement is supplementary reflow evidence, not actual browser-zoom approval.
