# U01-A: Action button adaptation

Date: 2026-11-15. Status: **verified** for native-button automated contracts and specimen review. Parent: [rebuild plan U01](../component-rebuild-plan.md), using [F01 foundations](F01-design-foundations.md).

## Scope and reference

Adapt the installed `src/components/ui/button.tsx` to the approved yellow/charcoal foundations. Consumers are future action controls and existing unmounted stock compositions such as carousel, calendar and dialog controls. Preserve their API compatibility without certifying their layouts. No navigation-link component, page section, public demo route, business action, form integration, loading state, toggle, provider or dependency belongs to this iteration. Supplied raster references remain unavailable; the agreed foundation contracts govern styling.

## Props, content and behavior

Keep `Button` and `buttonVariants`, native button props (including React 19 ref), `variant`, `size`, `className` and the existing `asChild` slot interface. Default native buttons to `type="button"`; explicit submit/reset types retain native behavior. Do not inject a default button type into slotted elements. Slot compatibility preserves element/attribute semantics; standalone navigation styling and missing-destination policy are specified in U01-B. Slotted Button anchor states remain for the actual CTA consumer task. (Resolved in [H01-A2](H01-A2-home-hero-design.md): hover/active selectors now use `not-disabled:`, identical for native buttons and applied to slotted links.) Only native enabled/disabled button state behavior is accepted here.

Content is caller-supplied action text or a labeled icon. An icon-only consumer supplies an accessible name, and decorative SVGs use aria-hidden. Do not invent labels from icons, replace visible labels with tooltips, uppercase text globally or truncate long labels. Native disabled buttons remain disabled, cannot activate and are skipped by Tab. Keep ref, event, ARIA, data and form attributes working. Arbitrary ARIA attributes are forwarded, but this task does not implement toggle/validation behavior or its state styling.

| Variant     | Normal appearance                                                                       | Hover / pressed                                                                      |
| ----------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| default     | Primary yellow, primary foreground and opaque primary border.                           | Primary-hover / primary-active backgrounds; unchanged foreground/border.             |
| secondary   | Secondary surface/foreground, essential input border.                                   | Accent surface with foreground; selected surface/foreground/border when pressed.     |

| ghost       | Transparent with local foreground; no essential boundary claimed.                       | Accent pair; selected pair/border when pressed.                                      |
| destructive | Local background with destructive text/border; no new destructive action is introduced. | Muted then selected surface; destructive text/border stay opaque.                    |
| link        | Transparent, underlined local link text; remains a button action.                       | Accent then selected surface/pair; underline remains. Navigation links are separate. |

All disabled variants use opaque disabled/disabled-foreground tokens and input border, opacity 1 and a not-allowed cursor. Enabled hover/active treatments must not override disabled colors. Native-button selectors require a separate anchor review when implementing button-shaped CTAs; U01-B uses a standalone NavigationLink. Require 4.5:1 for text and applicable 3:1 essential control boundaries against their surrounding surface in light/yellow/charcoal contexts. A yellow primary fill supplies the boundary on charcoal; its dark border supplies the boundary on light/yellow. Do not reduce whole-button opacity or use translucent palette substitutions.

Use Inter 500, 1rem/1.4, normal letter spacing, natural wrapping, 8px control radius and a minimum 44px target. Preserve all existing size names: default/xs/sm use minimum 44px targets with progressively different horizontal padding (16/8/12px); lg has minimum 48px height and 24px horizontal padding. Icon/icon-xs/icon-sm use minimum 44px targets; icon-lg uses 48px. Compact aliases change padding/glyph size, not touch accessibility or text size. No fixed height may clip wrapped text. Caller class overrides remain possible and need review in their actual composition.

Use the F01 control motion role (150ms, ease-out, color/background/border/opacity only), no pressed translation, and the protected 3px focus outline/3px offset. Reduced-motion preferences remove role transitions. Actual sticky/clipping contexts, grouped controls, menus, dialogs and other stock consumers need their own acceptance checks.

## Evidence and limitations

Before implementation, the default-type component test failed and the five compatibility tests passed. All five desktop browser cases failed against the unchanged stock Button/export: transparent essential borders, a 32px default height, the accessibility/focus case, two unintended native form submissions from Enter/Space, and transition-all remaining under reduced motion.

Only the Button source changed at runtime. It now consumes the existing semantic colors, typography, touch/radius and motion roles, retains the six variants/eight size names and defaults native actions safely. A hash audit confirmed all 127 captured route/style/content/input/package/other-component files remain unchanged, including both pre-existing lockfiles. No dependency, global stylesheet, business record, original asset or public demo route was introduced.

Two test-fixture issues were diagnosed after the first implementation run. The essential-boundary assertion incorrectly required the dark primary border itself to contrast with charcoal despite the yellow fill already supplying the boundary; it now checks the actual applicable border/fill contrast. The enlarged-text overflow was an unconstrained native fixture input (438px wide), with no overflowing Button; its test-only label/input now fit their parent. No production overflow was hidden and no contrast threshold was reduced.
