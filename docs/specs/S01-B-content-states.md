# S01-B: Content states

Status: **verified for the documented scope**. Date: 2026-11-16. Item 6 in the [13-item pre-Home checklist](../pre-home-checklist.md).

## Purpose and boundary

Provide one reusable, static presentation for missing information, an empty collection or unavailable content. These conditions share a heading and explanatory paragraph; their meaning comes from accurate consumer-owned copy and data checks, not different colors or invented business facts. Start with the real empty Programs catalog. No approved design reference is available; use the verified foundations and installed shadcn Empty composition, subject to visual approval.

This task does not rebuild catalog cards, search/filter no-results behavior, page introductions, legal/detail sections, loading/error recovery, forms or services. It does not insert preview records into real catalogs. Other pages keep their existing placeholders until their individual section tasks. All 24 templates remain in scope.

## Contract

- `ContentState({ title, description })` is a Server Component. Both props are required plain-text strings. The consumer owns whether it renders; the component has no fetching, data lookup, variant, action, arbitrary children, heading-level option or local state.
- Compose installed shadcn `Empty` and `EmptyHeader` with a real H2 and paragraph. Use it as a direct subsection below a page H1; deeper hierarchy requires its own future specification. Do not use the stock div-based title as a semantic heading. Escape text normally through React.
- This is static explanatory content, with no alert/status/live region, autofocus, Tab stop, retry, disabled action, fake link or decorative animation. Keep page-level recovery navigation outside the component.
- Add a small Zod-validated UI-copy record in `src/content/content-states.ts`. Programs title: **“Program information is not available yet”**. Description: **“No approved program details have been supplied for this website.”** This describes the website's inputs, not the gym's offerings, an operating status or a publication promise. Existing business catalogs and supplied copy remain unchanged.
- On `/programs/`, replace only the rebuild paragraph when `catalogs.programs.length === 0`. The empty state must not render when approved records exist; retain the existing rebuild paragraph for that unfinished populated presentation. Preserve the Programs H1, Back to home link, metadata, root preview notice, header/footer and route. Do not add preview cards or claim the populated catalog is implemented.
- Presentation: semantic background/foreground and muted description, decorative semantic border, 12px card radius, 24px padding and 8px heading/body gap. The containing page owns outer layout/gutters. H2 uses the existing fluid Barlow Condensed 600 hierarchy; body uses Inter 400, 16px/1.6, maximum 65ch. Wrap long text without truncation, clipping or fixed height. Use the same contract on light/yellow/charcoal surfaces; no new palette or CSS tokens.
- Verify reflow at 320/375/768/1280/1920px and doubled/spaced text. Keep the static message readable with blocked fonts, reduced motion, forced colors and JavaScript disabled. Preserve skip-link focus and recovery access. Fixtures stay in tests, outside real catalogs and public routes.
