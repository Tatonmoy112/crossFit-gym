## Definition of done for each iteration

1. Define one selected component, section or small behavior in `docs/specs/`: purpose, consumers, reference, content, props, states, responsive behavior, accessibility and exclusions.
2. Specify acceptance cases with stable IDs, scenarios, expected results and verification methods. Break implementation into small ordered steps mapped to those cases.
3. Write relevant automated tests before implementation and record failure for the expected missing behavior. Preserve existing passing regressions. A documentation-only specification records the test matrix without claiming executable tests exist.
4. Implement one behavior at a time with the smallest necessary client boundary; make its tests pass, then refactor. Reuse actual shared patterns and avoid tests that mirror CSS/source text or duplicate library internals.
5. Integrate only the relevant placeholder sections and update obsolete shell assertions. Keep one H1, valid associations, route metadata, preview separation and noindex rules.
6. Verify responsive layouts, keyboard/focus, reduced motion and relevant empty/error/selected states. Run the complete README workflow for route, layout or interaction changes; use appropriate documentation checks for documentation-only work. Record automated/manual results and unresolved visual/content/integration limits separately.
7. Update the specification, this backlog and `component-inventory.md` with actual evidence. Track **specified -> tests written -> implemented -> verified**; a test matrix is not executable coverage and a placeholder page is not complete. End the iteration at the selected task boundary.
