# Architecture

## Shared footer redesign

[L03-B](specs/L03-B-footer-redesign.md) keeps one Footer after main across the entire site and custom 404. FooterCallToAction is a Server Component composing Container, SectionHeading and a Button/NavigationLink Contact action. Footer composes a second Container, white Card, BrandLink and original contact/navigation/social/legal content; the decorative wordmark is isolated from meaningful content. Validated footer content owns CTA copy, source-derived tagline and wordmark. Named Card container queries control four/two/one navigation columns and meta reflow. Local footer CSS was created before its global import. No pathname boundary, client state, provider, route, dependency or release-policy change is introduced; native no-JavaScript navigation and modal isolation remain.

## Homepage features integration

## Current hero integration

[H01-A3](specs/H01-A3-home-hero-redesign.md) keeps HomeHero server-rendered and introduces its dedicated statistics slot. The homepage chooses validated real statistics or the preview-only fallback inside that slot, without nested section Containers or a separate counter band. ## Current reset state

The UI was reset on 2026-11-15. All 24 templates remain in Next.js App Router as Server Component route shells. Each route renders a heading and recovery links; Programs now replaces its rebuild notice with a conditional empty-content explanation. Other routes retain their rebuild notice. The homepage temporarily links to every currently exported page. The new root header composes BrandLink and both navigation variants. The root footer reuses original destinations and supplied contact/social channels. The global preview notice is removed; local missing-content and example-statistics disclosures remain. Other page sections and interactive features await rebuilding.

The root layout provides document metadata, a first-tab skip link, the server-composed Header, a focusable main landmark and the server-rendered Footer after main. At the owner's request the full official shadcn/ui library was subsequently installed: 63 local UI modules, support hooks/utilities and components.json. The configuration uses Radix Nova, neutral colors, Lucide icons, RSC and TSX. Global CSS imports Tailwind 4, shadcn and animation styles, defines light/dark tokens and preserves focus/reduced motion. Temporary document defaults live in the base layer. The pnpm 10.34.9 lockfile was updated in place for library dependencies.

[F01-A local fonts](specs/F01-A-local-fonts.md) uses one server-side `src/styles/fonts.ts` module with next/font/local. Root variables map Inter 400/500/600 to font-sans and Barlow Condensed 600/700 to font-heading. The five local WOFF2 files use swap/system fallback and on-demand loading; synthetic font styling is disabled. Source revisions, hashes and licenses live alongside the font assets, with exact license copies exported from public/fonts/licenses. No remote build/runtime font service or client provider is required. F01-C supplies heading sizing and F01-D supplies section-owned layout roles. Static browser QA owns port 3100 by default (PLAYWRIGHT_PORT override) and refuses existing servers, preventing accidental development-server reuse.

[F01-B semantic colors](specs/F01-B-semantic-colors.md) places surface/state values and protected focus in `src/styles/colors.css`. Globals maps these values into Tailwind/shadcn roles and uses bounded CSS scopes for dark utilities. Explicit light/charcoal/yellow surface attributes resolve locally, including nested light resets; root stays light independent of OS preference. Actual portal contents must carry an explicit surface marker. Other component-specific alpha/disabled/selected variants remain unadapted until their own tasks; U01-A separately adapts native Button states. Chromium specimens cover contrast, states, inheritance and system focus; other engines and real component compositions remain pending review.

[F01-C typography](specs/F01-C-typography.md) separates base body/H1/H2/H3 defaults from opt-in component-layer text roles in `src/styles/typography.css`. Roles provide display, control/emphasis, hint and 65ch reading measure without changing semantics. Tailwind utilities can override these defaults. The browser root size stays unforced; rem/fluid sizes and inherited wrapping support user text preferences. No component or route is added.

[F01-D layout/motion](specs/F01-D-layout-motion.md) separates layout/geometry (`src/styles/layout.css`) from opt-in transitions/reduced-motion protection (`src/styles/motion.css`). Main is a full-width landmark; all 24 existing shell sections explicitly use `layout-container py-8`. Future full-width section backgrounds contain their own inner container. The skip link adopts touch sizing, and the noninteractive main landmark uses inset focus to stay inside viewport edges. Explicit radius/touch/motion roles do not adapt stock modules or create components.

[U01-A Button](specs/U01-A-button.md) consumes foundation roles inside the existing CVA API. Native buttons default to a non-submitting type; explicit form types and React 19 refs/ARIA/event props remain intact. Slot rendering receives no injected type. Actual-component server markup is used in isolated browser fixtures and React event forwarding is covered by Testing Library. Navigation links and actual stock compositions remain separate; no page receives a demo control or client provider.

[U01-B NavigationLink](specs/U01-B-navigation-link.md) is a provider-free wrapper using the existing Next Link for root-relative paths (prefetch disabled) and native anchors for HTTP(S), mailto, tel and named fragments. Native props/refs and explicit aria-current remain caller-owned; no route-matching state is introduced. Missing/unsupported targets throw a generic TypeError. Explicit new tabs merge protective rel tokens and visible/accessibly named copy. Existing foundation roles supply link states, wrapping and minimum 44px targets. Only About's recovery link is integrated, preserving its label/destination, route metadata and Server Component boundary.

[L01-A BrandLink](specs/L01-A-brand-link.md) composes NavigationLink and a local unoptimized Next Image without a client provider or new state. The validated brand record derives its name from site.name; destination and identity are fixed, with className as its only public prop. A decorative 44px square mark sits beside the visible Inter name, with an accessible Home cue. The 192px/2,604-byte WebP preserves the selected source's white plate; a manifest records source/output hashes and encoding. Existing PNG inputs remain untouched. L01-B mounts BrandLink in the real root header.

[L02-A desktop navigation](specs/L02-A-desktop-navigation.md) separates server-side navigation validation from a small client disclosure boundary. Zod checks canonical internal targets, unique groups/destinations and relationships to fixed routes/approved locations while retaining all supplied values. The client consumes plain groups and usePathname; the closest boundary-delimited match selects one exact page or ancestor location. Native navigation/lists compose shadcn Collapsible with adapted Button/NavigationLink. Local state holds one open group; outside pointer/focus listeners clean up when closed/unmounted, Escape restores its trigger, and Arrow Down enters an open panel. A pathname-keyed child resets disclosure state on route changes. No new app provider, global state or dependency is introduced. L01-B mounts this component in the root header.

Other UI components remain unmounted in the route shells. Tooltip, toast and optional theme providers should be introduced only with features that use them. Mobile detection and carousel external-state subscriptions use useSyncExternalStore with stable server snapshots and subscription cleanup. See [component-inventory.md](component-inventory.md) and [shadcn-setup.md](shadcn-setup.md).

## Retained foundation

Business data lives in src/content/. Zod validates field shapes. Relationship validation rejects duplicate slugs/identifiers and invalid program/coach/location/membership associations. Catalog lookup keeps structure previews separate from actual records.

Build flow: supplied/approved inputs -> local modules -> Zod parsing -> relationship validation -> Server Component route shells -> metadata -> static export. Dynamic routes enumerate actual records and isolated preview slugs at build time; unknown slugs return 404. All 24 template categories remain in scope.

Route metadata, canonicals, robots and sitemap generation remain. Indexing defaults off and requires site.preview=false, an HTTPS site URL and explicit indexability configuration. Preview detail records remain noindex. Location and article JSON-LD previously lived in presentation code; reintroduce it with their rebuilt pages using verified, approved facts only.

Inquiry validation and its optional typed transport remain in src/lib/forms/inquiry.ts. No transport is configured and no form UI is currently rendered. Only confirmed provider acceptance may produce a success result when that UI is rebuilt.

Static export uses trailing directory indexes and unoptimized local images. No API route, server action, runtime image server, CMS, backend or global state provider is required. The build wrapper normalizes Windows RSC segment filenames after Next builds; always use pnpm build. The local export server serves directory indexes and 404.html, supports gzip and caches hashed framework assets. This reset does not edit supplied inputs or assets. Concurrent brand-image changes were left untouched; see qa-checklist.md for retained image references that need reconciling.

## Rebuild architecture

Follow [component-rebuild-plan.md](component-rebuild-plan.md). Build agreed design foundations, accessible primitives, the global shell and real shared sections before composing page-specific features. Keep routes compositional. Reuse components only for genuinely shared structure; avoid unrelated optional-prop renderers. Default to Server Components and introduce client boundaries only for interactions. Keep interactive state local or in URL parameters.

Public launch still requires approved content/legal text, domain/hosting configuration, visual review and full QA. A working shell export is not a completed UI or release approval.

[L02-B mobile navigation](specs/L02-B-mobile-navigation.md) uses a matching server/client boundary. The schema import is type-only in the client; validated groups arrive as serializable props. Both navigation variants use a shared canonical-path/longest-ancestor matcher. The client keeps modal state local and resets it on pathname change. Installed shadcn Dialog root/trigger/portal/close and Radix modal content provide trapping, isolation and scroll lock. A scoped light portal surface prevents inherited charcoal tokens from being lost. A cleaned-up 64rem media subscription dismisses on desktop; the existing focusable main landmark is the fallback when its Menu trigger becomes hidden. L01-B verifies the combined App Router and responsive behavior. No global provider or dependency is added.

[L01-B header assembly](specs/L01-B-header-assembly.md) keeps Header a Server Component and both navigation state boundaries local. A full-width charcoal banner owns its existing constrained inner layout and wraps the brand/controls when needed. The skip link stays above it in paint and Tab order. Both variants subscribe to the same 64rem boundary and release hidden focus to the stable main landmark. The shared `useNavigationFocus` hook preserves focus ownership through CSS-triggered blur before the media event, clearing it on ordinary exit; it adds no provider/global state. Actual static-export browser tests verify App Router transitions and history with a persistent document sentinel; no-JavaScript checks cover the server brand/Home and recovery content, while menus require JavaScript.

[L03-A footer](specs/L03-A-footer.md) remains a Server Component after main and reuses BrandLink/NavigationLink plus the validated original navigation. `src/content/footer.ts` derives supplied contacts/channels from site.ts, validates HTTPS/telephone/unique social values and reuses registered-route validation for legal destinations. Legal approval flags determine the availability note. Intrinsic navigation columns respond to available space and text size; the footer adds no client state, provider or service. All links remain available without JavaScript. Map directions are an existing address search, not a verified pin.

[S01-A preview notice](specs/S01-A-preview-notice.md) is a Server Component at the beginning of main. It reads site.preview directly and renders no markup when false. A small validated UI-copy record remains separate from real catalogs. The installed Alert instance uses role=note instead of its default urgent alert; it has no live region, focus target, local state or dismissal. The global preview flag and independent indexability prerequisites retain their existing meaning; metadata/robots/sitemap/preview-record code is unchanged. Configuration tests cover an otherwise indexable fixture as well as blocked configurations, without changing the real preview flag.

[S01-B content states](specs/S01-B-content-states.md) retains installed Empty as its shell; S03-B now supplies the semantic H2/paragraph group through SectionHeading. Required title/description props share one static structure across missing, empty and unavailable meanings; consumers own accurate copy and visibility. A Zod-validated UI record supplies Programs copy. Only the empty Programs catalog consumes it now; populated presentation retains its explicit rebuild placeholder. No live region, action, client state, preview record, dependency or public fixture route is added.

[S03-A Container](specs/S03-A-container.md) is a native div Server Component using the existing layout-container class and installed cn utility. Native props/React 19 ref are forwarded; className supports consumer spacing/grid/flex. Programs now owns a full-width outer section with this constrained inner wrapper. It adds no tokens, implicit semantic/focus role, clipping, provider or dependency. Other direct CSS consumers remain unchanged; accidental nested Containers would add another set of gutters.

[S03-B SectionHeading](specs/S03-B-section-heading.md) is a Server Component for an H2 with an optional nonblank description, logical start/center alignment and optional caller-owned heading ID. It consumes foundation typography/colors and adds no H1, generated copy, state, action, provider or dependency. ContentState uses its center mode; page H1, Container, metadata and data conditions remain unchanged. Other sections are future consumers.
